# Float Friends 账号云同步与服务器并行部署计划

## 用户需求

- Float 改造成访客拿到链接即可注册、登录和使用的朋友版本。
- 账号登录后，角色、聊天、设置、创作内容和媒体数据应能备份到云端，并可从云端恢复。
- 不在登录页增加与使用无关的提示；必要的开源声明放在“关于与声明”。
- 使用用户现有云服务器部署。默认与当前 momo 并行运行在独立端口，等待用户配置二级域名后再接入 HTTPS，避免直接覆盖现有生产站点。
- Float Friends 作为独立 AGPL 项目发布，不与闭源 momo 源码合并。

## 关键决策

1. 继续使用 Float 现有 Supabase 账号表和 Session Cookie，不另建第二套登录系统。
2. 复用现有按模块、内容哈希、分片上传、异常隔离和滚动保留的云备份引擎。
3. 新增账号托管云存储模式。浏览器不接触 `service_role`，所有对象访问通过同源服务端 API。
4. 服务端从 Session 解析当前账号，并在对象路径前强制增加账号 ID；客户端不能指定、读取或删除其他账号路径。
5. 托管存储使用独立私有 bucket，不与用户个人云 bucket 混用。
6. 登录账号默认开启账号云备份；保留手动“立即备份”和“云端恢复”。
7. Self-hosted 单机模式继续保留原来的个人 Supabase 配置，不强制切换托管模式。
8. 朋友版使用独立 Compose 项目、目录、容器和端口；不执行任何会停止、覆盖或删除 momo 容器、目录、数据库或卷的操作。
9. 首次部署先通过 `服务器IP:独立端口` 验收。二级域名确定后再配置 Caddy/HTTPS。

## 实现阶段

### 阶段 1：账号托管存储协议

- 扩展 `CloudBackupConfig`，区分个人 Supabase 与账号托管模式。
- 新增 `/api/account-cloud-storage`：创建 bucket、上传、下载、列举和删除。
- 校验对象路径、请求体大小、登录状态和账号状态。
- 保留现有上传分片、重试、清单和恢复格式。

### 阶段 2：自动备份与恢复 UI

- 登录账号首次进入时自动配置托管模式和后台备份。
- 数据管理页显示“账号云备份”，不再要求普通朋友部署自己的 Supabase。
- 保留云端备份列表与合并恢复。
- 登录页保持简洁，移除临时的本地数据说明。

### 阶段 3：验证

- TypeScript、定向 lint、生产构建。
- 未登录访问存储 API 返回 401。
- 非法路径和超大对象被拒绝。
- 登录账号只能访问自身前缀。
- 浏览器验证登录页、数据管理云备份状态和恢复入口。
- 使用两个账号验证对象目录隔离。

### 阶段 4：并行部署

- 新增独立 Dockerfile、Compose 和部署脚本。
- 在远端创建 `/root/float-friends`，保留发布备份和持久化数据。
- 使用独立 Compose 项目 `float-friends` 和独立监听端口。
- 部署前检查 momo 容器和站点健康；部署后再次验证，确保没有影响。
- 输出待配置的二级域名反代目标。

## 验收标准

- 新用户使用有效邀请码完成注册并获得 HttpOnly Session。
- 登录后不需要填写 Supabase 地址或密钥即可进行云备份。
- service role、账号密钥和管理密钥不进入浏览器构建产物。
- 同账号可以在另一浏览器登录并从云端恢复数据。
- 不同账号无法列出或下载彼此备份。
- Float Friends 可通过独立服务器端口访问。
- 当前 momo 正式站点、数据库、容器和静态文件不发生变化。

## 外部依赖收口

- 账号、Session 与云备份已经改为服务器本地 SQLite + 持久卷，不再依赖 Supabase。
- 首次上线使用 `float.154.219.105.171.sslip.io` 提供 HTTPS；自有二级域名后续替换。
- 对应部署版本发布到公开仓库 `https://github.com/afufu/float-friends`。
