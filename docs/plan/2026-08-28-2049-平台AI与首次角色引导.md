# Float Friends 平台 AI 与首次角色引导计划

## 用户反馈

- 登录后只能看到前端界面，聊天、查手机和剧情等核心 AI 能力没有开箱即用。
- 朋友拿到链接后不应再自行准备 API 地址、模型名或密钥。
- 新账号需要清楚、简短地完成首个角色创建，然后进入可用桌面。

## 根因

1. Float 原版将 LLM API 配置保存在每个浏览器本地，新账号没有有效密钥。
2. 新账号没有角色卡，聊天和多数角色内容功能没有可操作主体。
3. 用户当前仍可能打开旧的 localhost 预览，而不是正式 HTTPS 地址。

## 关键决策

1. Float 浏览器只调用同源 `/api/platform-ai/v1`，不接触真实 Gateway Token。
2. 服务端代理只允许 `GET models` 和 `POST chat/completions`，限制请求体大小并要求有效 Float Session。
3. 服务端通过 Docker 内网调用 momo AI Gateway，令牌只写入服务器 `.env`。
4. 登录账号自动写入固定 `platform-managed` API 配置，并设为全局默认；已有个人配置保留但不作为默认。
5. 新账号云恢复完成后，如果没有角色，显示首次角色引导；已有云端角色绝不覆盖。
6. 首次角色创建只要求角色名和一句设定，保存后同步创建联系人和私聊会话。
7. 平台 AI 与角色数据继续进入账号云备份。

## 验收标准

- 浏览器构建产物和网络请求中不出现真实 Gateway Token。
- 未登录调用平台 AI 返回 401。
- 已登录账号请求模型清单返回受管模型配置。
- 已登录账号可通过同源代理获得真实模型回复。
- 新账号首次登录必须先完成角色创建。
- 创建后角色出现在角色 App 和聊天联系人中。
- 同账号换设备恢复后不重复出现首次引导。
- 正式域名和 momo 站点同时保持 200。

## 执行记录

- 已新增同源平台 AI 代理，只允许模型清单与对话补全。
- 已验证未登录 401、登录后模型清单和模型回复正常。
- 已确认浏览器占位 Key 不参与上游鉴权，真实 Token 只由服务端环境注入。
- 已在账号云恢复完成后写入 `platform-managed` 配置并设为全局默认。
- 已增加首次角色引导，创建角色时同步建立联系人与私聊会话。
- 平台托管模式下不再向普通用户展示大模型 API 配置入口。
